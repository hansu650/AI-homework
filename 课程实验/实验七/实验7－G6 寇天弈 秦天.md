## 一、实验目的
- 掌握提示工程的基本方法，能够通过角色、任务、步骤和格式约束引导大模型完成作文批改任务。
- 理解检索增强生成（RAG）的工作原理，能够基于本地企业政策文档构建智能问答系统。
- 理解 Agent 的思考-行动-观察循环，能够设计简单的信息收集与整理工作流。
- 综合运用 LLM API、向量检索、FAISS 和工具调用模拟解决实际问题。
- 培养对模型输出进行来源核查、事实核查和质量评估的意识。

### 3.1 提示工程实践
本部分实现“智能作文批改助手”。CRISPE 提示词明确背景、角色、输入、步骤、限制和评价格式，并与模糊提示词进行对比。

#### 完整 CRISPE 提示词
```text

C - Context（背景）：这是一篇初中生短文，老师需要你做基础语文批改，重点关注错别字、病句、评分与总体评价。
R - Role（角色）：你是认真、客观、表达温和的语文作文批改助手。
I - Input（输入）：作文题目和正文如下。
题目：难忘的运动会
正文：今天学校举行了一年一度的运动会。早晨操场上人山人海，同学们都非常兴奋。我报名参加了八百米比赛，刚开始我跑得很快，可是到了第二圈就觉得胸口很闷，脚步也慢了下来。班主任在跑道边不停给我鼓厉，同学们也喊着我的名字。听到大家的加油，我仿佛又有了力气，终于坚持到了终点。虽然我没有取得第一名，但是我明白了坚持比名次更重要。这次运动会让我受益非浅，也让我更加热爱班集体。
S - Steps（步骤）：
1. 通读全文，只依据作文原文进行判断，不要虚构不存在的问题。
2. 标注作文中的错别字，给出“原词/正确写法/说明”；如果没有错别字，写“未发现明显错别字”。
3. 找出至少 1 处病句或表达不顺的句子，给出修改建议。
4. 从内容、结构、语言三个维度打分，每项满分 10 分，并给出一句理由。
5. 给出 50 字以内的总体评价，语气鼓励但要指出改进方向。

## 4. 总体评价（50字以内）
```

- 加载 TXT 文档并清洗文本。

- 使用 FAISS IndexFlatIP 存储和检索。
- 将检索片段交给 DeepSeek 生成回答并保留来源。

### 3.3 简易 Agent 设计
本部分模拟“信息收集与整理 Agent”，主题为“人工智能在医疗领域的应用”。Agent 通过 search_tool 和 summarize_tool 展示三轮思考-行动-观察循环。

#### 工具定义代码/伪代码
```python
def search_tool(query: str, top_k: int = 4) -> ToolResult:
    return ToolResult(tool_name='search_tool', input={'query': query}, output=results[:top_k])

def summarize_tool(search_results: list[dict]) -> ToolResult:
    return ToolResult(tool_name='summarize_tool', input={'result_count': len(search_results)}, output=summary)
```

#### 三轮思考-行动-观察记录
| 轮次 | 思考 | 行动 | 观察 | 下一步 |
|---:|---|---|---|---|
| 1 | 先明确主题并收集基础资料，优先获取应用场景、价值和风险信息。 | `search_tool({'query': '人工智能在医疗领域的应用', 'top_k': 4})` | 搜索工具返回 4 条结果，覆盖影像诊断、临床决策、药物研发和隐私安全。 | 继续整理 |
| 2 | 搜索结果已经覆盖多个角度，下一步调用摘要工具提炼关键发现。 | `summarize_tool({'result_count': 4})` | 摘要工具生成了主题概述、3个关键发现、风险提示和信息来源列表。 | 生成报告 |
| 3 | 信息已足够生成结构化报告，检查报告是否包含主题概述、3个关键发现和来源。 | `generate_agent_report(summary)` | 报告已生成，包含主题概述、关键发现、风险提示和模拟来源，任务完成。 | 任务完成 |

#### 简要分析
Agent 难点在于任务拆解、工具选择、状态维护、观察结果判断和停止条件。模拟结果能体现流程，但真实应用还需要检验搜索来源和摘要准确性。

## 四、结果分析
1. 提示词中哪个要素对输出质量影响最大？明确的角色、任务目标和约束条件都重要，其中输出格式和评价标准影响最大。它直接要求模型按“错别字、病句、三维评分、总体评价”输出，减少遗漏。
2. RAG 系统在面对知识库外问题时表现如何？股票期权问题被系统判断为知识库外问题并拒答，提示没有相关政策依据，避免了编造公司制度。
3. Agent 设计的难点是什么？难点在任务拆解、工具调用顺序、观察结果判断、上下文状态维护，以及何时结束循环并生成最终报告。

## 五、遇到的问题及解决
- 在 Windows PowerShell 中并行执行多个 conda run -n DL 命令时，Conda 临时文件被占用。解决方法是改为串行检查，并直接调用 DL 环境 Python。
- 使用 conda run 捕获中文输出时出现 GBK 编码异常。解决方法是设置 PYTHONUTF8=1、PYTHONIOENCODING=utf-8，并直接调用 DL 环境 Python，最终 DeepSeek 版主脚本返回 0。
- 实验依赖最初未完整安装。解决方法是在 DL 环境中安装 openai、zhipuai、faiss-cpu、python-dotenv、pypdf、langchain、python-docx、jupyter 等必要包，没有安装 GPU、CUDA 或大模型权重。
- Notebook 执行时出现 nbformat 缺少 cell id 和 Windows zmq 事件循环警告，但不影响执行结果，最终生成了 exp7_llm_rag_agent_executed.ipynb。
- DeepSeek 主要用于聊天生成，未额外调用 embedding API。RAG 部分使用 deterministic hash embedding 兜底，并通过 FAISS 完成检索。

## 六、实验总结
本实验通过提示工程、RAG 和 Agent 三部分，理解了大语言模型应用开发的基本流程。提示工程说明清晰角色、任务和输出格式能提升稳定性；RAG 通过本地政策文档检索为回答提供依据，降低幻觉风险；Agent 则用思考-行动-观察循环模拟多步骤任务处理。后续可加入更严格的相似度阈值、真实搜索工具和自动评估指标。

### RAG 回答核心函数
```python
def answer_with_rag(
    question: str,
    rag_index: RagIndex,
    embedding_client: EmbeddingClient,
    chat_client: ChatClient,
    top_k: int = 4,
) -> Dict[str, object]:
    query_vec = embedding_client.embed_texts([question])
    retrieved = rag_index.search(query_vec, top_k=top_k)
    context = "\n\n".join(
        [
            f"[来源{i + 1}] 文件：{item.chunk.source}；片段：{item.chunk.chunk_id}；相似度：{item.score:.4f}\n{item.chunk.text}"
            for i, item in enumerate(retrieved)
        ]
    )

    in_scope = is_question_in_scope(question, retrieved)
    if not in_scope:
        answer = "知识库中未找到与该问题直接相关的政策依据，因此无法回答。建议咨询人力资源部或查看补充制度文件。"
    else:
        user_prompt = f"""
请只根据下面的企业制度资料回答问题。若资料中没有明确依据，请直接说明“知识库中未找到相关依据”，不要编造。

问题：{question}

资料：
{context}

输出格式：
回答：用 2-5 句话给出结论。
依据：列出使用到的来源文件名。
""".strip()
        answer = chat_client.chat(
            system_prompt="你是企业制度问答助手，必须基于给定资料回答，并保留来源。",
            user_prompt=user_prompt,
        )

    return {
        "question": question,
        "answer": answer,
        "sources": [
            {
                "source": item.chunk.source,
                "chunk_id": item.chunk.chunk_id,
                "score": round(item.score, 4),
                "text_preview": item.chunk.text[:120] + ("..." if len(item.chunk.text) > 120 else ""),
            }
            for item in retrieved
        ],
        "in_scope": in_scope,
    }
```
